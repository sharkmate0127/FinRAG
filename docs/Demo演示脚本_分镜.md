## 🎬 分镜表

> 口播词 = 照着念的解说；操作 = 屏幕上做的事；[字幕] = 后期可加的关键词条。

### 场景 0｜开场（0:00 - 0:30，30 秒）

**画面**：浏览器打开 Gradio 页面（顶栏大标题），鼠标缓慢划过界面组件。

**口播**：
> 这是我用 6 周从零开发的 **FinRAG 金融研报智能问答系统**。它内置了 20 份券商深度研报的知识库，覆盖宁德时代、比亚迪等 11 家上市公司。系统基于 RAG + Agent 双架构——研报内容问答走 RAG 检索增强，实时行情走 Agent 工具调用。下面完整演示一遍。

**[字幕]**：RAG 文档问答 + Agent 实时数据 + 引用溯源 + 双通道

---

### 场景 1｜RAG 事实问答 + 引用溯源（0:30 - 1:10，40 秒）

**画面**：模式选 **rag**，输入框敲入问题。

**口播**：
> 先看研报问答。问一个事实类问题：**"宁德时代的主营业务是什么？"**

**操作**：
1. 输入 `宁德时代的主营业务是什么？` → 回车
2. 停顿 2-3 秒等回答出现
3. **鼠标移到右下角"引用来源"框**，逐条指出文件 + 页码

**口播**（接上）：
> 回答明确给出动力电池系统和储能系统两大主业，并且带上了 2024 年的收入占比数据。关键是——**右下角有完整的引用来源**，标注了出自哪份研报、哪一段。这样每条答案都可溯源、可验证，从机制上抑制了大模型幻觉。

**[字幕]**：答案→引用 一一对应；引用来源：文件名+页码

---

### 场景 2｜数值推理问答（1:10 - 1:45，35 秒）

**画面**：模式仍 rag，输入框换问题。

**口播**：
> 再看金融场景最看重的数值推理能力。问：**"宁德时代 2024 年的预测营收是多少？"**

**操作**：输入 `宁德时代2024年的预测营收是多少？` → 回车 → 展示回答

**口播**（接上）：
> 系统从盈利预测表格里准确提取出预测营收数字，并且标注了单位、数据来源是开源证券的盈利预测表。数值题最容易让大模型瞎编，我们的 Few-Shot 引导让它在表格数据上做精确提取和计算。

**[字幕]**：数值精确提取 + 单位标注 + 来源标注

---

### 场景 3｜Agent 实时数据查询（1:45 - 2:30，45 秒）

**画面**：模式切到 **agent**，输入框敲实时行情问题。

**口播**：
> 刚才都是研报里的静态内容。如果问研报之外的信息呢？——把模式切到 **agent**，问实时行情：**"比亚迪今天的股价是多少？"**

**操作**：
1. Radio 从 rag 切到 agent（鼠标点击，让切换动作明显）
2. 输入 `比亚迪今天的股价是多少？` → 回车
3. 回答出现后，**鼠标指到"模式/工具调用"框**，展示 LLM 自主决定调用了 get_stock_price 工具

**口播**（接上）：
> 大家看左下角——大模型**自主判断这个问题需要查实时数据**，于是调用了股价查询工具。这就是 Function Calling：研报问答只能回答"研报里写了什么"，加上 Agent 之后，系统能回答"现在发生了什么"。网络不可用时还会自动降级到本地演示数据，不会崩溃。

**[字幕]**：LLM 自主调工具 get_stock_price；三级降级：真接口→演示数据→明确报错

---

### 场景 4｜RAG + Agent 协同推理（2:30 - 3:05，35 秒）

**画面**：模式 agent，输入协同对比问题。

**口播**：
> 最有意思的是 RAG 和 Agent 的**协同**。问一个需要两边配合的问题：**"研报预测比亚迪 2026 年净利润约 629 亿，它现在的市值大概是多少？"**

**操作**：输入问题 → 回车 → 展示回答同时引用研报（RAG 侧）和实时/工具数据（Agent 侧）

**口播**（接上）：
> 这类"研报预测 vs 实际数据"的对比问题，单一技术答不了——系统会**同时走 RAG 拿到研报预测，走 Agent 拿到当前市值**，再综合推理。这就是"研报说了什么"和"现在市场怎么定价"的交叉验证。

**[字幕]**：hybrid 混合路由：RAG（研报预测）+ Agent（实时市值）→ 协同综合

### 场景 5｜双通道切换（3:05 - 3:45，40 秒）

**画面**：切到终端窗口（PowerShell）。

**口播**：
> 最后展示架构亮点——**双模型双部署**。我用环境变量一键切换通道：云端 DeepSeek 保证质量，本地 Qwen2.5-7B INT4 保证离线可用。

**操作**：
1. 终端演示（两条命令，快切）：
   ```powershell
   $env:FINRAG_MODEL_MODE = "api"
   python -c "from ask import ask; print(ask('比亚迪2026年归母净利润预测是多少？')[0][:80])"
   $env:FINRAG_MODEL_MODE = "local"
   python -c "from ask import ask; print(ask('比亚迪2026年归母净利润预测是多少？')[0][:80])"
   ```
2. 指向两条输出的模型名/回答差异（本地那行注明走 Ollama）

**口播**（接上）：
> 同一份知识库、同一个问题，两条通道都能答。本地这条跑在我的 RTX 4060 上，8G 显存做 INT4 量化完全够用。日常开发用 API，离线演示用本地，这就是可落地的模型调度策略。

**[字幕]**：FINRAG_MODEL_MODE = api / local；同一模型不同部署 = 严谨对照实验

## 🎯 面试问答弹药（录完视频后背下来）

- **为什么双通道都用"同一模型"的两种部署？** 本地只能跑 7B 级蒸馏版（与 API 千亿级 MoE 差一个量级），Qwen2.5-7B 与 API 行为一致、量化损耗可控 → 同一模型的两种部署才构成**严谨对照实验**。
- **Context Recall 为什么两通道一模一样？** 0.556=0.556 是因为 Recall 只取决于**共享的检索器**，与生成模型无关——这恰好证明瓶颈在检索层（源头候选池 top20 未捞全），下一步扩大候选池/语义分块。
- **Prompt 为什么能 +48.6%？** P3 = 角色 + 防幻觉约束 + 数值标注 + 综合分析引导（人工 1-5 分 1.75→2.60）。
