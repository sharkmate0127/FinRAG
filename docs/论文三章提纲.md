# 第一章 引言（目标 1800 字，Day1-2）

## 1.1 研究背景与选题动机（约 500 字）
- **痛点引入**：券商研报是投研核心信息源，但海量、专业、时效强——普通投资者阅读门槛高（可用数据：知识库 20 份研报覆盖 11 家公司 5 个方向）。
- **LLM 的机遇与局限**：大语言模型具备通用问答能力，但存在三个硬伤：① 幻觉（编造不存在的数字）；② 知识截止（训完后不知道新研报）；③ 无法访问私有/增量文档（研报不入训练语料）。
- **类比金句（可写进引言）**：让 LLM"裸答"研报问题 = 闭卷考试；RAG = 给它一份研报的"开卷考试"——从外部知识库检索相关段落再作答。
- **引出方案**：在 RAG 之上，金融问答还缺两类能力：数值推理（研报盈利预测表）与实时数据（股价行情）——引出 Agent 工具调用与协同路由。

## 1.2 问题定义与挑战（约 450 字）
定义任务：给定券商研报语料库与自然语言问题，输出**忠于原文、带引用溯源**的回答。按问题类型拆解（对应评测集 5 类）：
| 类型 | 示例 | 核心挑战 |
|---|---|---|
| 事实问答 | 宁德时代主营业务 | 忠实度 + 引用可溯 |
| 数值推理 | 2024 预测营收 | 表格提取、防编数 |
| 实时数据 | 今天股价 | 时效性（RAG 答不了） |
| 对比/协同 | 预测 vs 实际 | 多源信息综合 |
| 推理 | 因果/影响分析 | 检索覆盖 + 多步推理 |

四大技术挑战：① 幻觉控制（Faithfulness）；② 数值可信；③ 检索召回完整性（Context Recall）；④ 本地资源受限下的部署与评估（8G 显存）。

## 1.3 研究内容与主要贡献（约 500 字，答辩重点）
- **贡献 1｜RAG + Agent 双能驱动架构**：按问题意图路由（rag/agent/hybrid），突破"只能答研报内容"的边界，支持"研报预测 vs 实际数据"综合对比。
- **贡献 2｜双模型双部署对照**：DeepSeek API（云端）与 Qwen2.5-7B INT4（本地 Ollama）双通道，同一模型两种部署构成严谨对照，为资源受限场景提供模型调度依据。
- **贡献 3｜面向金融的 Prompt 与数值策略**：P3 模板（角色+防幻觉约束+数值标注+综合分析）经 A/B 测试提升 48.6%（1.75→2.60）；数值 Few-Shot 引导表格提取。
- **贡献 4｜量化评估体系**：71 题混合类型评测集（reference 全部校对为研报原文）+ RAGAS 四指标（judge 中立 DeepSeek），双通道完整评测（见 `docs/双通道对比报告.md`）。

## 1.4 论文组织结构（约 300 字）
第二章相关工作 → 第三章系统设计 → 第四章实验与评估（用 `docs/消融实验汇总表.md` 做主表）→ 第五章总结与展望（Recall 0.556 局限 + 扩大候选池/语义分块方向）。

# 第二章 相关工作（目标 2200 字，Day3，参考文献 >15 篇）

> 批判性写法模板：**前人做了什么 → 局限是什么 → 本项目怎么补**。每节至少 3-5 篇文献。

## 2.1 检索增强生成（RAG）技术演进（约 700 字）
- **Basic RAG（Naive RAG）**：索引→检索→生成三段式（Lewis et al., 2020 原论文）。局限：相似度检索对词面不匹配敏感、无排序优化、长文档信息分散。
- **Advanced RAG**：混合检索（BM25 稀疏 + 向量稠密互补）、重排（cross-encoder reranker）、查询改写/多路召回。点出本项目对应实现（BM25+向量 top20 融合 → bge-reranker → top8）。
- **Modular / Agentic RAG**：将检索做成模块与工具，支持路由、规划、多步（可引 2024-2025 综述）。批判：多数开源项目止步 naive 或仅 demo，**缺少金融垂直场景的系统落地与量化评估**——本项目补位。
- 图：可放「Basic → Advanced → Modular」演进图（自绘，第三章架构图也复用）

## 2.2 金融领域 NLP 与金融大模型（约 600 字）
- 金融专用模型路线：FinBERT（Araci 2019）、BloombergGPT（2023，500 亿金融语料预训练）、FinGPT、国内 Tongyi-Finance / 轩辕 等。
- **批判（关键）**：金融大模型预训练/微调成本高（数据、算力），且**通用金融语料 ≠ 个股研报私有领域**——新发研报无法实时进模型。
- 本项目定位论证：不微调、走 **RAG 外挂知识库**——增量文档即插即用、答案可溯到原文，对个人/中小团队更可行。（呼应导师方案"为什么要做 RAG 而非微调"的必问题）

## 2.3 文档问答与金融研报问答（约 500 字）
- 通用文档问答：开放域 QA 数据集与系统（SQuAD、HotpotQA 多跳等）→ 局限：多为公开百科语料。
- 金融文档问答难点：**表格结构、数值单位、长文档章节跳读、中英混杂、专业术语缩写**。
- 现有研报问答方案局限：① 多数不提供引用溯源，答案不可验证；② 数值问题易编造；③ **无公开、可控的评测基准**（研报版权限制数据难共享）。
- 本项目应对：块级元数据（券商/日期/代码）+ 编号引用 [n] + 71 题 reference 原文化评测集（可复现）。

## 2.4 生成质量评估：从传统指标到 LLM-as-Judge（约 400 字）
- 传统：BLEU/ROUGE 基于词面重叠，对"语义正确但表述不同"的金融答案误判严重。
- RAGAS（Es et al. 2023）：Faithfulness（忠实度）/ Answer Relevancy（相关度）/ Context Precision（上下文精确率）/ Context Recall（上下文召回率）。
- 批判：judge 自身有偏（故本项目固定 DeepSeek 为中立裁判）；**Context Precision/Recall 高度依赖 reference 质量**——本项目 71 题 reference 全部校对为研报原文，才让 0.444→0.556 的修复被真实观测到（呼应早期评测全 0 的教训，见 `docs/RAGAS评估报告.md` 与 README 早期记录）。

> 📌 文献 >20 篇获取渠道：必读《金融大语言模型》（熊鹏等）第 1-3 章引用；CNKI 搜"检索增强生成 金融"；Google Scholar 搜 RAGAS / Retrieval-Augmented Generation for LLMs (Gao et al. 2023 综述) / FinBERT / BloombergGPT / Function Calling / Tool Learning。

# 第三章 系统设计（目标 2300 字，Day4，核心章：让读者能复现）

## 3.1 总体架构（约 450 字）
- **架构图**：用 `docs/week5_1.png` / `FinRAG_系统架构图文字说明.docx`（工作区）升级版，标注 4 层：
  1. 交互层：Gradio（对话+引用+工具可视化）/ FastAPI（/health /query /agent_query）
  2. 路由与调度层：意图分类（rag/agent/hybrid）+ 双通道模型调度（`FINRAG_MODEL_MODE`）
  3. 核心能力层：混合检索（BM25+向量）→ 重排 → 上下文构建 → Prompt 生成；Agent Function Calling（工具：get_stock_price / get_financial_data）
  4. 数据层：20 份研报 → 1323 块 → bge-large-zh 嵌入 → ChromaDB；akshare 数据源
- 技术选型表：直接引用 README 技术栈表（LangChain/ChromaDB/bge 双模型/Ollama/FastAPI/Docker）。

## 3.2 数据处理与知识库构建（约 500 字，可复现流程）
1. **采集**：20 份券商深度研报（开源/东吴/国元/民生/东莞/华安/华鑫/信达/上海/新时代），11 家公司、5 个细分方向（列表见 README 知识库节）。
2. **解析清洗**：PDF 文本抽取 → 去页眉页脚/免责声明噪声（scripts: `parse_pdfs.py`）。
3. **分块**：500-1000 字符/块，**带元数据**（`chunk_id`/`source_file`/券商/日期/股票代码/块序号）→ 1323 块（`chunk_texts.py`）。
   - 设计理由：研报表格与段落同块保留，支撑数值提取；元数据支撑引用溯源到"文件+页码段"。
4. **向量化入库**：bge-large-zh-v1.5（1024 维）→ ChromaDB（`build_vector_db.py`）。首次需下载模型约 1.3GB，国内走 hf-mirror。

## 3.3 RAG 检索与生成核心算法（约 550 字）
- **混合检索**：稀疏 BM25 + 稠密向量各自取 top20 → 融合候选 → 公式给 RRF/分数归一合并式（按实际实现写）。
- **重排**：bge-reranker-large（cross-encoder，max_len 512）对候选精排 → 取 **top8**（消融定稿：top5 Recall 0.444 → top8 0.556，top10 持平且 Precision 降——说明见消融表）。
- **引用溯源**：生成时对每个事实句标注 [n]；返回 `chunks[id2idx[cid]]` 元数据 → 渲染"来源：文件名-页码/块"。检查脚本 `check_citations.py` 保证引用块确含所述信息。
- **Prompt 设计（P3）**：角色（金融研究助手）→ 防幻觉约束（只答检索内容、不编数）→ 格式约束（引用+数值单位标注）→ 综合分析引导（多块/多公司对比时主动归纳）。A/B：P0 1.75 → P3 2.60（+48.6%）。
- **数值推理 Few-Shot**：在 Prompt 中附 2-3 个"表格→数值答案"示例，引导从盈利预测表精确取值（数值类准确率 70%）。

## 3.4 Agent 模块与 RAG+Agent 协同（约 450 字）
- **Function Calling**：LLM 自主决定调用工具（OpenAI 兼容协议 / LangChain Tool Calling）。
- **工具与三级降级**：`get_stock_price`/`get_financial_data`：akshare 真接口 → 本地演示数据 → 明确报错（网络不可用不崩溃）。
- **路由机制**：意图分类 rag（研报问题）/ agent（实时问题）/ hybrid（对比协同）——Day25 实测路由准确率 100%（10/10）。
- **协同示例**："研报预测 2026 净利 vs 当前市值" → 同时走 RAG 拿预测 + Agent 拿实时 → 综合推理（对应 `rag_agent.py`）。

## 3.5 双通道模型调度与部署（约 250 字）
- 通道 A：DeepSeek API（deepseek-chat，云端，质量优先）；通道 B：Qwen2.5-7B INT4（Ollama，本地，离线可用）。
- 决策依据：本地 8G 显存只能跑 7B 级；INT4 量化（4.7GB）保行为一致；同一模型两种部署才构成严谨对照（详细取舍见方案 2.1）。
- 调度：环境变量 `FINRAG_MODEL_MODE` 切换，评测/日常两场景分离。
- 部署：FastAPI + Dockerfile/compose；Gradio 交互界面（`app_gradio.py`）。

## 3.6 评估方法与评测集构建（约 150 字，承上启下到实验章）
- 指标：RAGAS Faithfulness / Answer Relevancy / Context Precision / Context Recall（judge 固定 DeepSeek、temp=0，保证裁判中立；AnswerRelevancy strictness=1 兼容 DeepSeek 单采样）。
- 评测集：71 题（事实 46/数值 10/Agent 7/对比 4/推理 4），reference 从研报原文逐条校对（`qa_pairs_71_final.json`）。
- 本章"可复现"自检清单：读者照 README 命令能否跑通全流程与评估（见 README 快速开始 + 数据准备 + RAGAS 段）。

# ⚠️ 写作避坑（论文扣分点）
1. **数字口径统一**：论文只认 **71 题 reference 原文化**评测数字；10 题早期全 0 是评测集缺陷，只作为"迭代过程"讲，不能当结论。
2. **消融表措辞**：明确写"开发期各模块独立验证口径"（主观分/MRR/路由准确率），避免被质疑"不同基准不可比"；若导师要求严格同基准消融，方案见消融表第四节。
3. **引用溯源别过度承诺**：实现是"文件名+块号"，写"段落"前先核对 `check_citations.py` 的输出格式。
4. **Context Recall 0.556 必写进"局限与展望"**：写"候选池源头漏检"（top8→top10 不涨是证据），并提出扩大候选池/语义分块方向——比回避更能体现研究素养。
